# 화면: 온보딩 / 업체 프로필 등록

**목적:** 신규 업체 담당자가 계정을 만들고, 매칭에 필요한 최소 정보(업종 물품분류 prefix·활동 지역)를 등록해 첫 매칭이 가능한 상태로 만든다.
**진입 경로:** 서비스 랜딩 페이지의 "무료로 시작하기" 버튼, 또는 로그인하지 않은 사용자가 보호된 화면에 접근했을 때의 리다이렉트.

## 레이아웃

단계형(스텝) 등록 흐름이다. 각 스텝은 화면 상단의 진행 표시(현재 스텝 / 전체 5스텝)와 하단의 이전/다음 이동 요소를 공유한다.

1. **스텝 1 — 계정·사업자 정보**
   - 사업자등록번호 입력(10자리, 저장 시 암호화 대상)
   - 업체명 입력
   - 담당자 이메일 입력
   - 개인정보 수집·이용 동의 체크박스 (**필수** — 미체크 시 다음 스텝으로 진행 불가)
2. **스텝 2 — 업종 선택**
   - **자유 텍스트 입력이 아니다.** 물품분류 대분류(2자리) → 중분류(4자리) 계층 트리에서 다중 선택하는 컴포넌트다. 대분류를 펼치면 하위 중분류 목록이 나타나고, 대분류 자체만 선택해도 되고 중분류까지 내려가 선택해도 된다.
   - 선택한 코드는 **선택한 깊이 그대로** 저장된다 — 8자리 품명분류까지 내려가도록 강제하지 않는다 (`D-06`, `docs/design/업종-물품분류-매핑.md` §프로필 저장 형식 권장안).
   - 목표 업종 4개를 트리 상단에 추천 항목으로 노출한다: 정보통신·소프트웨어개발(대분류 43), 사무용품(대분류 44), 인쇄·출판(대분류 55), 시설관리. **각주:** 시설관리는 물품분류번호 체계에서의 정확한 코드가 아직 확정되지 않았다 — `docs/design/업종-물품분류-매핑.md` §미확인 항목과 확인 방법 1번 참고. 확정 전까지는 추천 목록에 "코드 확인 중" 표시를 달아 노출하거나, 사용자가 직접 트리에서 검색해 선택하게 한다.
   - 안내 문구: "선택 범위가 넓을수록(대분류만) 더 많은 공고가, 좁을수록(중분류까지) 더 적고 정확한 공고가 매칭됩니다."
3. **스텝 3 — 활동 지역**
   - 시/도 단위 다중 선택 (예: 서울특별시, 경기도)
4. **스텝 4 — 실적·인증 (선택)**
   - 실적 항목 반복 입력: 사업명, 계약금액, 계약일자, 발주기관
   - 인증 항목 반복 입력: 종류, 번호, 만료일
   - **건너뛰기 가능.** 이 스텝을 필수로 만들면 입력 부담이 커져 온보딩 완주율이 떨어진다(`CLIENT-05`) — 실적·인증은 매칭 가중치 보조 신호일 뿐 매칭 성립의 필수 조건이 아니므로, 나중에 프로필 화면에서 채워도 무방하다.
5. **스텝 5 — 알림 채널 초기 설정**
   - 이메일 채널 기본값 on (변경 가능)
   - 푸시·상세 임계값 등 나머지 세부 설정은 이 스텝에서 다루지 않고 "알림 설정 화면으로 이동" 링크로 연결한다.

## 상호작용

- 대분류 항목의 펼침 아이콘을 클릭 → 하위 중분류 목록이 아코디언으로 펼쳐진다.
- 중분류 체크박스를 여러 개 선택 → 선택된 항목이 화면 상단 "선택됨: N개" 칩 목록에 실시간으로 추가된다.
- 업종을 하나도 선택하지 않은 채 "다음" 클릭 → 다음 스텝으로 진행하지 않고 "업종을 1개 이상 선택해주세요" 인라인 오류를 표시한다.
- 스텝 1에서 사업자등록번호 10자리 입력을 완료 → 형식 검증(자릿수·체크섬)을 즉시 수행하고, 통과하면 다음 필드로 포커스가 이동한다.
- 스텝 4에서 "건너뛰기" 버튼 클릭 → 실적·인증 입력 없이 스텝 5로 즉시 이동하며, 나중에 프로필 화면에서 추가할 수 있다는 안내를 짧게 노출한다.
- 스텝 5에서 "완료" 클릭 → 등록을 마치고 공고 피드(`02-feed.md`)로 이동한다. 이때 등록된 업종 prefix·지역이 세션에 저장되어 피드의 첫 매칭 스코프로 쓰인다(`00-user-journey.md` §화면 간 데이터 인계 계약).

## 데이터 소스

이 화면은 다음 테이블에 기록한다.

| 스텝 | 쓰는 테이블 | 비고 |
|---|---|---|
| 스텝 1 | `companies` | 사업자등록번호·업체명·이메일. 사업자등록번호는 **저장 시 암호화 대상**이며, 화면 재노출 시(예: 뒤로 가기, 프로필 재방문) 전체 자릿수를 그대로 표시하지 않고 앞 3자리 이후를 마스킹(`123-**-*****`)해 표시한다. 진위확인(`PROF-05`)은 국세청 사업자등록정보 진위확인 API 판정 결과의 상태값(확인됨/확인 중/불일치)만 화면에 표시하고, 원본 판정 로직은 이 화면에서 재구현하지 않는다. |
| 스텝 2 | `company_classification_codes` | 선택한 대분류/중분류 prefix를 그대로 저장 (`company_id`, `classification_code` 쌍) |
| 스텝 3 | `companies` | 활동 지역(시/도 코드) |
| 스텝 4 | `company_performances`, `company_certifications` | 건너뛰면 아무 행도 생성되지 않는다 |
| 스텝 5 | `notification_settings` | 채널 on/off 초기값 |

## 엣지 케이스

- **이미 가입된 사업자등록번호로 재가입 시도** — 스텝 1에서 저장 전 중복 체크를 수행하고, 이미 존재하면 "이미 등록된 사업자등록번호입니다. 로그인하시겠어요?" 안내와 로그인 화면 링크를 제공한다.
- **업종 미선택 상태로 다음 시도** — 스텝 2에서 최소 1개 이상 선택을 강제하고, 미선택 시 인라인 오류로 진행을 막는다(§상호작용 참고).
- **진위확인 API 지연·실패** — 등록 자체는 막지 않고 "확인 중" 상태로 계정을 생성한다(보류 상태로 통과). 근거: 외부 API 지연이 온보딩 완주(`CLIENT-05`)를 막아서는 안 되며, 진위확인은 사후에도 처리 가능한 보조 신호이기 때문이다. 최종 확인 실패 시 계정 상태를 "확인 필요"로 표시하고 이용에는 제한을 두지 않는다(자격 판별은 Phase 4 범위).
- **뒤로 가기 시 입력값 보존** — 스텝 간 이동 시 이전에 입력한 값(사업자등록번호, 선택한 업종·지역 등)은 화면 로컬 상태에 보존되어 다시 입력할 필요가 없다.
- **동의 체크박스 미체크 상태로 다음 시도** — 스텝 1에서 진행을 막고 "개인정보 수집·이용에 동의해주세요" 인라인 오류를 표시한다.
